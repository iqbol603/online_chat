# Как запустить и проверить индикатор "печатает..."

## 🚀 Быстрый запуск

### 1. Запуск Backend (в первом терминале)

```bash
cd backend

# Проверьте, что .env файл существует
# Если нет, скопируйте:
cp env.config .env

# Установите зависимости (если еще не установлены)
npm install

# Запустите сервер
npm run start:dev
```

✅ Backend запустится на `http://localhost:3000`

Вы должны увидеть:
```
🚀 Server running on:
   http://localhost:3000
   http://192.168.x.x:3000
📡 WebSocket available at:
   ws://localhost:3000
```

---

### 2. Запуск Frontend для клиентов (во втором терминале)

```bash
cd frontend

# Установите зависимости (если еще не установлены)
npm install

# Запустите dev сервер
npm run dev
```

✅ Frontend запустится на `http://localhost:3001`

---

### 3. Запуск Operator Panel (в третьем терминале)

```bash
cd operator-panel

# Установите зависимости (если еще не установлены)
npm install

# Запустите dev сервер
npm run dev
```

✅ Operator Panel запустится на `http://localhost:3002`

---

## 🧪 Проверка индикатора "печатает..."

### Шаг 1: Откройте два окна браузера

**Окно 1** - Клиент: `http://localhost:3001`
**Окно 2** - Оператор: `http://localhost:3002`

---

### Шаг 2: Войдите как оператор

В окне оператора (`http://localhost:3002`):

1. Введите email: `admin@example.com`
2. Введите пароль: `admin123`
3. Нажмите "Войти"

✅ Вы должны увидеть операторский кабинет с очередями

---

### Шаг 3: Начните чат как клиент

В окне клиента (`http://localhost:3001`):

1. Нажмите кнопку "💬 Чат" внизу справа
2. Заполните форму:
   - Имя: `Тестовый клиент`
   - Телефон: `+992987654321`
   - Язык: `Русский`
3. Нажмите "Начать чат"

✅ Откроется чат с ботом

---

### Шаг 4: Передайте диалог оператору

В окне клиента:

1. Напишите: `соединить с оператором` или `оператор`
2. Бот передаст диалог оператору

✅ В окне оператора появится новый диалог в очереди

---

### Шаг 5: Примите диалог оператором

В окне оператора:

1. В разделе "Очередь" нажмите на диалог с клиентом
2. Диалог откроется

✅ Теперь оператор и клиент могут общаться

---

### Шаг 6: Проверьте индикатор "печатает..."

#### Тест 1: Оператор печатает → Клиент видит

1. **В окне оператора**: Начните печатать в поле ввода
2. **В окне клиента**: Должен появиться индикатор:
   ```
   ● ● ● Оператор Иван набирает сообщение...
   ```
   (с анимированными точками)

3. **В окне оператора**: Остановите печатать на 2 секунды
4. **В окне клиента**: Индикатор должен исчезнуть

#### Тест 2: Клиент печатает → Оператор видит

1. **В окне клиента**: Начните печатать в поле ввода
2. **В окне оператора**: Должен появиться индикатор:
   ```
   ● ● ● Тестовый клиент набирает сообщение...
   ```
   (с анимированными точками)

3. **В окне клиента**: Остановите печатать на 2 секунды
4. **В окне оператора**: Индикатор должен исчезнуть

#### Тест 3: Отправка сообщения останавливает индикатор

1. **В окне оператора**: Начните печатать
2. **В окне клиента**: Должен появиться индикатор
3. **В окне оператора**: Нажмите Enter или кнопку "Отправить"
4. **В окне клиента**: Индикатор должен сразу исчезнуть

---

## ✅ Ожидаемое поведение

### Индикатор появляется:
- ✅ Когда пользователь начинает печатать
- ✅ С анимированными точками (три точки подпрыгивают)
- ✅ С именем пользователя: "XXX набирает сообщение..."

### Индикатор исчезает:
- ✅ Через 2 секунды бездействия (если пользователь перестал печатать)
- ✅ Сразу при отправке сообщения
- ✅ При получении события `typing:stop`

### Анимация:
- ✅ Три точки с эффектом подпрыгивания
- ✅ Плавное появление/исчезновение
- ✅ Стилизованный текст

## 🐛 Если что-то не работает

### Проблема: Индикатор не появляется

**Проверьте:**
1. ✅ Backend запущен на порту 3000
2. ✅ WebSocket подключение установлено (проверьте консоль браузера)
3. ✅ Диалог в статусе `in_progress` (не `bot` или `queued`)
4. ✅ Откройте консоль браузера (F12) и проверьте ошибки

**В консоли браузера должны быть:**
- `WebSocket connected`
- События `typing:start` и `typing:stop` в Network → WS

### Проблема: Индикатор не исчезает

**Проверьте:**
1. ✅ Таймеры очищаются при отправке сообщения
2. ✅ Событие `typing:stop` отправляется корректно
3. ✅ Проверьте консоль на ошибки JavaScript

### Проблема: Неправильное имя в индикаторе

**Проверьте:**
1. ✅ Имя оператора загружается из базы данных
2. ✅ Имя клиента передается при typing:start

---

## 📝 Дополнительные проверки

### Проверка WebSocket событий

Откройте консоль браузера (F12) → вкладка Network → WS:

**Клиент должен отправлять:**
- `client:typing:start` при начале ввода
- `client:typing:stop` при остановке/отправке

**Оператор должен отправлять:**
- `operator:typing:start` при начале ввода
- `operator:typing:stop` при остановке/отправке

**Backend должен отправлять:**
- `typing:start` с данными `{ conversationId, name }`
- `typing:stop` с данными `{ conversationId }`

## 🎯 Быстрая проверка одной командой

Если у вас установлен `concurrently`, можно запустить все сразу:

```bash
# В корне проекта создайте package.json с:
npm install -g concurrently

# Затем запустите:
concurrently \
  "cd backend && npm run start:dev" \
  "cd frontend && npm run dev" \
  "cd operator-panel && npm run dev"
```
